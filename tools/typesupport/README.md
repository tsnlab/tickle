# tickle-typesupport

Generates TickLE codecs (`<Name>.c` / `<Name>.h`) from ROS 2 `.msg` / `.srv` interface files.
See [`PLAN.md`](PLAN.md) for the full design and milestone plan, and "Interface serialization
(TickLE CDR-4)" in [`../../DESIGN.md`](../../DESIGN.md) for the wire format the generated codecs
implement.

**Status**: feature-complete through PLAN.md's M6 - scalars, strings, fixed/variable arrays
(with capacity resolution and default values), nested messages, `.srv` request/response pairs,
constants, and `*_encode_inplace`/`*_decode_inplace` for any message that's fully fixed-size or
ends in one prefix-aliasable trailing byte array. `.action` and multi-dimensional arrays are
explicitly out of scope (see PLAN.md).

Every one of TickLE's own real interfaces (`examples/{uint64,set_bool,ping_pong,perf}/*.msg`/
`*.srv`) is generated by this tool, not hand-written - see [`../../CONTRIBUTING.md`](../../CONTRIBUTING.md#generated-codecs)
for the edit-and-regenerate workflow.

## Setup

```sh
$ python3 -m venv .venv && . .venv/bin/activate
$ pip install -e .
```

## Use

```sh
$ tickle-typesupport --dump-ir some/Interface.msg     # parse and print fields/constants, no codegen
$ tickle-typesupport -O outdir/ some/Interface.msg     # generate outdir/Interface.{c,h}
$ tickle-typesupport -O outdir/ -I some/search/path some/Interface.srv   # resolve a nested type via -I
```

A nested field (`std_msgs/Header header`, say) is resolved from a `-I` search path (ROS 2's own
`pkg/msg/Name.msg` layout) if given, falling back to `tickle_typesupport.builtins`'s small
built-in copy of `builtin_interfaces/Time` and `std_msgs/Header` otherwise - see that module's
own docstring. Each distinct nested dependency gets its own `<pkg>__<Name>.h`/`.c` pair written
alongside the interface that needed it.

From the repo root, `make regen` re-generates every real interface in place - see
[`../../CONTRIBUTING.md`](../../CONTRIBUTING.md#generated-codecs).

## Tests

```sh
$ python3 -m pytest tests/
```

`tests/fixtures_ros2/` holds a handful of real ROS 2 interface files (`std_msgs/Header`,
`sensor_msgs/Image`, `geometry_msgs/Twist`+`Vector3`, `std_srvs/SetBool`,
`builtin_interfaces/Time`, `diagnostic_msgs/DiagnosticStatus` - fetched unmodified from
`ros2/common_interfaces` and `ros2/rcl_interfaces` @ `jazzy`) laid out in their real
`pkg/msg/Name.msg` form, since `_rosidl_parser` validates the message name derived from that
path - used for parser-fidelity testing (`test_parse_smoke.py`) and, for `Twist`/`Vector3`, to
exercise the `-I` nested-resolution path in the codegen tests too. `tests/fixtures_own/` holds
test-only interfaces that exist purely to exercise a specific generator feature (every array
shape, array defaults, nested messages) rather than to model a real TickLE example.

## Why a vendored parser

`tickle_typesupport/_rosidl_parser.py` is `rosidl_adapter/parser.py` from
[ros2/rosidl](https://github.com/ros2/rosidl) copied in verbatim (see the file's own header for
the exact commit) rather than a `pip` dependency: it's the canonical ROS 2 `.msg`/`.srv` grammar
(so compatibility is structural, not best-effort), it's stdlib-only, and vendoring one file
avoids version skew against whatever `rosidl-adapter` release happens to be on PyPI. It is
Apache-2.0 (see its header) and used here only as a build-time tool, never linked into
`libtickle`.
