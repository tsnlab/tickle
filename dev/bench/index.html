Two of the charts below are not a performance signal and are frozen.

rmw_tickle latency (buildfarm_perf_tests) and rmw_tickle throughput (buildfarm_perf_tests) ran both processes on the shared development machine. That box also runs CI runners, virtual machines and interactive work, and its own noise turned out to be the size of the effects being measured on it: between two measurement days it shifted every implementation by about 13µs — roughly a quarter of the figure — including two DDS vendors containing no TickLE code at all. TickLE therefore no longer publishes any performance number measured on that machine (decision of 2026-09-24). Performance is measured only on the dedicated Raspberry Pi rig, which is what every other chart on this page is.

These two stopped being updated on 2026-09-22 and are kept as history rather than deleted, because deleting the range would take this explanation with it. Two separate reasons not to read them as results: the venue above, and a transport defect — until commit 82a6a02d every TickLE node on a host bound only the well-known port, so a unicast addressed to it reached whichever socket bound last, sometimes the sender's own. In runs that passed and were recorded as clean, roughly 10% of the stream went to the sender instead of the subscriber.

See rmw_tickle/COMPARISON.MD §5 for what replaced them and what was lost with them, and rmw_tickle/PLAN.md milestone 67 for the defect. Every other chart on this page is unaffected — measured across two physically separate Raspberry Pis, which never shared a port and run nothing else.
