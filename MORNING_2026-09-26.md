# Overnight: what is good, which direction is right, and the evidence

Morning of 2026-09-26. What Plan and Dev did overnight, organised around the conclusions.

---

## 0. What to know first

**Every TickLE performance figure we had published was measured on an unoptimised build (`-O0`).**
Both DDS vendors were apt release packages (`-O2`). This covers COMPARISON.md, the 108-run
campaign, the single-packet sweep and the rmw comparison alike.

- Cause: `platform/linux/Makefile:28`'s `BUILD_TYPE ?= debug` gives `CFLAGS ?= -O0 -g`, and
  `build.sh` never passed `BUILD_TYPE`. `rmw_tickle/CMakeLists.txt` had no `CMAKE_BUILD_TYPE` at
  all, so colcon built it with no `-O` flag.
- Dev found it with objdump; I confirmed it independently from the build system.
- **Direction**: every part of the error ran against TickLE. No conclusion reverses; the margins
  only widen.
- **Fix**: `TICKLE_CORE_BUILD` now defaults to release, rmw/typesupport CMake default to Release,
  and every TickLE RESULT line carries a `core_build=` identity field.

## 2. The big win overnight: latency CPU

The campaign's **only CPU loss** was the latency cells - TickLE 6,516 against CycloneDDS's 200, a
33x deficit.

The cause was `tt_Node_poll(-1)` normalising to 100 us and therefore waking **ten thousand times a
second regardless of traffic**. Confirmed with strace: `ppoll` was 99.69% of system time, 38,503
calls in five seconds.

After changing it to wait for the scheduler, as you asked:

| | before | after |
|---|---|---|
| latency-cell ppoll (5 s) | 38,508 | **34** |
| idle node wakes/s | 948 | **3.5** |
| idle CPU duty | 0.900% | **below the measurement floor** |
| latency CPU/Msample | 6,516 | **156** |
| vs CycloneDDS | 33x **worse** | **33% better** |

## 3. Thread safety costs nothing

Your decision: a lock API in the HAL, core made thread-safe, lock-free where possible, fine-grained
if locks are unavoidable.

Dev built step 1 (one owner-tracked lock per node plus a lock-free inbox, free on an MCU via
`tt_THREAD_SAFE=0`). Verification: TSan reports 0 races, **and the same test reports 14 races
against the previous code** - the control that makes the 0 mean something.

The measurement reversed three times, and how that happened matters more than the conclusion:

| | measured at -O0 | measured at -O2 |
|---|---|---|
| thread-safety code | +121 ns | **-6 ns** |
| the locks themselves | -35 ns | below measurement |
| dynamic retry default | +128 ns | **-49 ns** |
| total | +250 ns | **effectively zero** |

**Every term of the "+250 ns regression" was an artefact of the unoptimised build.**

## 4. The retry-interval default: the decision is supported by measurement

Dynamic is now the default, as you preferred. The evidence points three ways:

- **Healthy link**: CPU -49 ns, throughput +0.9% (on the optimised build)
- **High-RTT link** (10 ms delay + 5% loss): **bandwidth -42.6%**, throughput -14.0%
- **c5**: sends 1.75% more samples while delivering +1.12% per byte

On a 10 Mbit/s 10BASE-T1S link bandwidth is the binding constraint, so -42.6% is worth far more
than -14%.

## 5. The item you deferred: the evidence got stronger

**IP fragmentation** (COMPARISON.md item 15). At P4 under 5% loss, **97.4% of reassembly attempts
fail** and only 1 datagram in 47 survives. The cause is the kernel, not TickLE, confirmed after
ruling out three in-core hypotheses each against its own control. Both DDS vendors never enter that
path, because they use `DATA_FRAG`.

That agrees with your judgement to skip it until `DATA_FRAG` exists - the measurement supports the
direction.

## 6. This class of defect will keep happening

Overnight we hit **the same defect six times**. Every one is "the measurement measured something
other than its name":

| What | How it looked | How it fails now |
|---|---|---|
| `-O0` core | plausible figures | `core_build=` asserted, dedicated prefixes |
| NDEBUG tests | **38/38 passing** (checking nothing) | `-UNDEBUG`, evidenced by `__assert_fail` references |
| retry mode | looked comparable | `retry_interval_cfg_ns=` asserted |
| stale DDS bindings | passed the gate | regenerated on size mismatch, compile refused on mismatch |
| `-i 0.1` default | `sent=5` printed ten times | a `sent == round(d/i)` gate voids the run |
| empty parse | "nothing wrong" | a zero-row parse exits non-zero |

**The rule: an identity field or a test only counts when the reader fails without it.**
